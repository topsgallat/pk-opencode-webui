# Docker Images

This directory contains Docker configurations for running OpenCode Web.

## Generic Image (`Dockerfile`)

An image that runs the UI server with an optional built-in OpenCode API. Suitable for:
- Standalone deployments (solo mode — API + UI in one container)
- Docker Compose setups with a separate API container
- General reverse proxy deployments (nginx, traefik)
- Kubernetes deployments (without Kubeflow)

### Build

```bash
# From repo root
docker build -f docker/Dockerfile -t opencode-web .
```

### Operation Modes

The image supports two modes via the `OPERATION_MODE` environment variable:

#### Solo mode (default)

Starts the OpenCode API server on port 4096, waits for it to be ready, then starts the UI server. Both processes run in the same container supervised by s6-overlay. Use this mode for standalone deployments where you want a self-contained environment.

During solo startup, the container also merges `mcp.playwright` into `~/.config/opencode/opencode.json` so Playwright MCP uses CloakBrowser automatically without replacing existing config.

#### UI-only mode

Only the UI server starts. It acts as a frontend for an external OpenCode API available at `API_URL`. This is useful when you already have an OpenCode backend running on your host machine or in another container.

### UI-only with Host Backend

When running in `ui-only` mode against a host backend, you often want to share the same sessions, projects, and configurations between your host and the container. This requires synchronizing environment variables and volume mounts.

#### Key Configuration Needs

- **`OPENCODE_WORKSPACE_ROOT`**: Set this to your host's home directory path (e.g., `/home/username`). This ensures that file paths generated by the host backend remain valid inside the container.
- **`API_URL`**: Point this to your host's OpenCode API. On Linux, use `http://host.docker.internal:4096`.
- **`extra_hosts`**: Required on Linux to resolve `host.docker.internal` to your host's IP.
- **Volume Mounts**: You must mount your host's home directory and the `.local/share/opencode` directory into the container at the exact same paths.

#### Docker Compose Example

```yaml
services:
  opencode-ui:
    build:
      context: .
      dockerfile: docker/Dockerfile
    ports:
      - "8080:8080"
    environment:
      - OPERATION_MODE=ui-only
      - BASE_PATH=/
      - HOME=/home/username
      - XDG_CACHE_HOME=/home/username/.cache
      - OPENCODE_WORKSPACE_ROOT=/home/username
      - API_URL=http://host.docker.internal:4096
    volumes:
      - /home/username:/home/username
      - /home/username/.local/share/opencode:/home/username/.local/share/opencode
    extra_hosts:
      - "host.docker.internal:host-gateway"
    user: "1000:1000" # Match your host user ID to avoid permission issues
    restart: unless-stopped
```

#### Troubleshooting UI-only Mode

- **Sessions not visible**: Ensure `OPENCODE_WORKSPACE_ROOT` in the container matches your host's home directory path. If they differ, the UI may look in the wrong place for session metadata.
- **API Connection Refused**: Verify that `API_URL` is reachable from within the container. On Linux, ensure `extra_hosts` is configured and that your host backend is listening on `0.0.0.0` or the Docker bridge IP.
- **Permission Denied**: Use the `user: "1000:1000"` directive (replacing with your actual UID/GID) to ensure the container can read and write to your mounted host volumes.
- **White Screen / No Projects**: Check the browser console and container logs. Usually, this indicates a mismatch between the `API_URL` and the actual backend location.

### Volume Mounts

**Option 1: Just for running projects (no config sync)**

Mount only the directory where your projects are:

```bash
docker run -p 8080:8080 \
  -e OPERATION_MODE=solo \
  -e HOME=/projects \
  -v /path/to/projects:/projects \
  opencode-web
```

```yaml
services:
  opencode:
    build: .
    ports:
      - "8080:8080"
    environment:
      - OPERATION_MODE=solo
      - HOME=/projects
    volumes:
      - /path/to/projects:/projects
```

**Option 2: With home directory (full config)**

```bash
docker run -p 8080:8080 \
  -e OPERATION_MODE=solo \
  -e HOME=/home/username \
  -v /home/username:/home/username \
  opencode-web
```

```yaml
services:
  opencode:
    build: .
    ports:
      - "8080:8080"
    environment:
      - OPERATION_MODE=solo
      - HOME=/home/username
    volumes:
      - /home/username:/home/username
```

**How it works:**
- `HOME` tells OpenCode where to look for config and where projects are stored
- OpenCode cache and config are automatically symlinked to container's directories to avoid conflicts
- Container uses its own internal configs (`.config/opencode`, `.cache/opencode`)

**Note on non-home volumes:** If you mount a non-home directory, ensure `.config` and `.cache` directories exist:

```bash
mkdir -p /path/to/projects/.config /path/to/projects/.cache
```

### Syncing Config from Host to Container

If you want to use your existing OpenCode configs (MCP servers, skills, agents) in the container:

```bash
# 1. Copy configs from host to container
docker cp ~/.config/opencode/. <container-name>:/home/<USER>/.config/opencode/
docker cp ~/.cache/opencode/. <container-name>:/home/<USER>/.cache/opencode/

# 2. Restart the container to load the new configs
docker restart <container-name>
```

**Example with docker-compose:**
```bash
# Copy configs (replace USER with your username and container name with yours)
docker cp ~/.config/opencode/. opencode:/home/USER/.config/opencode/

# Restart
docker restart opencode
```

**What gets synced:**

| Directory | Contents | Notes |
|----------|----------|-------|
| `oh-my-opencode.json` | Agent models, categories | ✅ Portable |
| `skills/` | Custom AI skills | ✅ Portable |
| `mcp-servers/` | MCP server configs | ⚠️ May need reinstallation |
| `agent/` | Agent configurations | ✅ Portable |
| `workflow/` | Workflow configs | ✅ Portable |
| `node_modules/` | Dependencies | ⚠️ Will be reinstalled |

**Note:** Configs stored in the container layer will persist after container recreation, but will be lost if the image is rebuilt. For permanent storage, consider using a Docker volume instead of bind mounts.

### Environment Variables

| Variable               | Default                 | Description                                          |
|------------------------|-------------------------|------------------------------------------------------|
| `OPERATION_MODE`       | `solo`                  | `solo`: API + UI together; `ui-only`: UI server only |
| `HOME`                 | `/root`                 | Home directory (set to mounted path for projects)     |
| `PORT`                 | `8080`                  | Port the UI server listens on                        |
| `API_URL`              | `http://127.0.0.1:4096` | OpenCode API server URL (used in `ui-only` mode)     |
| `BASE_PATH`            | `/`                     | URL prefix for reverse proxy support                 |
| `BRANDING_NAME`        | (empty)                 | Optional branding name shown in UI                   |
| `BRANDING_URL`         | (empty)                 | Optional URL for branding link                       |
| `XDG_CACHE_HOME`       | (empty)                 | Path for cache files (see Security Warning below)    |
| `XDG_CONFIG_HOME`      | (empty)                 | Path for config files (see Security Warning below)   |
| `OPENCODE_SERVER_PASSWORD` | (empty)             | API server password (recommended for production)     |

## Security Warning: Config/Cache Path Isolation

> **Important:** Never set `HOME`, `XDG_CONFIG_HOME`, or `XDG_CACHE_HOME` to your real host paths (e.g. `/home/user/.config`, `/home/user/.cache`, `/root/.config`, `/Users/yourname/.config`, etc.) inside the container.
>
> - **If you set these variables to your real host paths and mount them into the container, the container will read and write directly to your host's config and cache.**
> - This can cause config conflicts, data corruption, or security risks if the container and host use different OpenCode versions or environments.
> - The container may overwrite, delete, or expose sensitive files from your host.
>
> **Best Practice:**
> - Use a dedicated, isolated directory for OpenCode container config and cache, such as `/tmp/opencode-home` or `/home/user/opencode-container-config`.
> - Mount only the specific project/session directory you want to sync, not your entire home directory or `.config`/`.cache`.
> - Example (safe):
>   ```bash
>   docker run -p 8080:8080 \
>     -e HOME=/tmp/opencode-home \
>     -e XDG_CACHE_HOME=/tmp/opencode-home/.cache \
>     -e XDG_CONFIG_HOME=/tmp/opencode-home/.config \
>     -v /path/on/host/opencode-home:/tmp/opencode-home \
>     opencode-web
>   ```
> - If you want to sync a project/session, mount only that folder:
>   ```bash
>   docker run -p 8080:8080 \
>     -e HOME=/projects \
>     -e XDG_CACHE_HOME=/projects/.cache \
>     -e XDG_CONFIG_HOME=/projects/.config \
>     -v /home/user/mysession:/projects/mysession \
>     opencode-web
>   ```
>
> **If you use `/tmp` as the config/cache location and do not mount a volume, all data will be lost when the container restarts.**
> To persist data, always mount a Docker volume or bind mount to the config/cache directory.

## Kubeflow Image (`kubeflow/Dockerfile`)

A full-featured image for Kubeflow Notebooks that includes:
- OpenCode CLI pre-installed
- s6-overlay process supervisor
- Kubeflow-compatible user (jovyan, UID 1000)
- Automatic home directory setup for PVCs

See [kubeflow/README.md](kubeflow/README.md) for details.

### Build

```bash
# From repo root
docker build -f docker/kubeflow/Dockerfile -t opencode-web-kubeflow .
```
